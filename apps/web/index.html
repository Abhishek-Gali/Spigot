    What Kind of Documentation Does Spigot Need? (Valid vs. Blocked)

    ✅ Valid Input: Concrete HTTP REST API Reference

    Must document an actual HTTP service with a Base URL, Authentication, and HTTP Verb + Path endpoints (see examples/01_payments_api_manual.pdf or examples/02_support_tickets_api.md): 

    # StripeFlow Payments & Treasury REST API (v2.4)
Base URL: https://api.stripeflow.dev
Authentication: Send Authorization: Bearer <token> on all requests.

## Retrieve Payment Charge
GET /v1/charges/{charge_id}
- charge_id (path, string, required): Unique payment charge ID (ch_...)

## Create Payment Charge
POST /v1/charges
- customer_id (body, string, required): Customer ID to bill
- amount_cents (body, integer, required): Charge amount in minor units
- currency (body, string, required): ISO-4217 currency code (USD, EUR)

    ❌ Blocked Input (NOT_API_DOCUMENTATION)

    Spigot fails closed instead of guessing endpoints when given non-endpoint documents: 

    1. Framework / Standard Metaschemas:
   e.g. microprofile-openapi-spec-4.0-RC3.pdf
   (Documents Java @Operation annotations, not a live HTTP server's endpoints)

2. Language Client SDK Manuals:
   e.g. docs-python-telegram-bot.pdf
   (Documents Python classes like bot.send_message() without HTTP verbs/URLs)

3. Marketing / Conceptual Overview Pages:
   e.g. "About OpenAPI" articles with no Base URL or endpoint definitions
